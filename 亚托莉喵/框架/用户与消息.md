# 消息

[文档目录](../%E4%BB%8B%E7%BB%8D.md)

## 用户与会话

| 场景 | 用户 | 消息 | 会话标识 |
| --- | --- | --- | --- |
| QQ 群聊 | `QQUser` | `QQMessage` | 群 OpenID |
| QQ C2C | `QQUser` | `QQMessage` | 用户 OpenID |
| QQ 文字子频道 | `QQGuildUser` | `QQGuildMessage` | 子频道 ID |
| QQ 频道私信 | `QQGuildUser` | `QQGuildMessage` | 私信会话的 guildId |
| Napcat 群聊 | `NapcatUser` | `NapcatMessage` | 群号码 |
| Napcat 私聊 | `NapcatUser` | `NapcatMessage` | 用户 QQ 号码 |

`User` 提供平台、用户标识、名称、机器人标记、账号查询和权限判断，`Message` 提供平台、消息 ID、内容、时间戳和提及用户列表

平台消息中缺失的数据不会由框架保证补全，时间戳保持平台来源格式，不是统一的时间对象

`QQUser.getUnionOpenId()` 返回 QQ 开放平台绑定的互联 ID，发送者取自 `author.union_openid`，群消息中被 @ 的用户取自对应 mention 的 `union_openid`，未携带时为 `null`。该字段与 `getUserId()` / `getUserOpenId()` 独立保存；后者在群聊中为 `member_openid`，在 C2C 中为 `user_openid`，用于现有消息发送、账号查询和权限判断

## QQ 用户字段

群消息、群 @ 消息及 C2C 消息中的用户均使用 `QQUser`，群消息提及列表中的用户同样保留各自的资料

| 方法 | 来源与含义 |
| --- | --- |
| `getUsername()` | 平台用户名，独立于群昵称 |
| `getAvatar()` | `avatar` 中的头像 URL，未携带时为 null |
| `getMemberNickname()` | `member_nickname` 中的当前群昵称，未携带时为 null |
| `getMemberRole()` | QQ 平台的 `member_role`，类型为 `PlatformRole`；C2C 固定为 OWNER |
| `getUnionOpenId()` | 当前用户数据中的 `union_openid` |
| `getData()` | 构造用户时传入的原始用户 JSON |

群 @ 消息和全量群消息的 `mentions` 分别解析每名用户的头像、群昵称、互联 ID 及平台角色。字段缺失时保持为空，不使用消息发送者的资料填充被提及用户

::: important 频道用户标识
QQ 频道用户的 `getUserId()` / `getChannelUserId()` 是频道用户 ID，`getUnionOpenId()` 是 QQ 开放平台绑定的互联 ID，取自 `union_openid`，可能为空，两者不能替换使用。频道事件及 `QQGuildCommandSender` 同样通过 `getUnionOpenId()` 提供互联 ID
:::

::: note 平台角色与机器人权限
`isPlatformAdmin()` 查询平台角色，`hasPermission()` 查询机器人管理权限，群主身份不会自动等同于机器人管理员
:::

平台身份统一通过 `getMemberRole()` 读取，原 `getRole()` 调用需迁移到该名称。C2C 的 OWNER 表示当前私聊场景的身份约定，机器人账号角色仍通过 `getAccount()` 及 `hasPermission()` 查询

`QQUser.isBlocked()` 合并封禁与忽略状态，`QQGuildUser` 和 `NapcatUser` 当前默认返回 false，业务限制需要由运行服务补充

`Platform` 保留部分外部适配器使用的枚举值，不表示 core 内包含 Discord 或 KOOK 连接实现

## QQ 群与消息上下文

`QQGroup` 保存群 OpenID 与群统一 OpenID，群事件通过 `event.getGroup()` 提供该对象；群指令通过 `QQCommandSender.getGroup()` 获取同一实例，私聊指令返回 null

```java
var group = event.getGroup();
String groupOpenId = group.getGroupOpenId();
String unionGroupOpenId = group.getUnionGroupOpenId();
```

`unionGroupOpenId` 取自 `union_group_openid`，平台未携带时为 null。群场景始终构造群对象，标识是否有效仍取决于收到的数据。手动创建及发送、查询、成员管理入口见 [QQGroup](../QQ%E5%AE%98%E6%96%B9%E6%9C%BA%E5%99%A8%E4%BA%BA/%E6%9C%BA%E5%99%A8%E4%BA%BA%E4%B8%8E%E7%BE%A4%E8%B5%84%E6%96%99.md#qqgroup)

`QQMessage` 保存消息 ID、正文、时间、提及列表、附件、Ark、引用信息和原始报文，群标识由接收事件或指令发送者提供。原 `getConversationId()`、`getUnionGroupOpenId()` 调用应迁移到群上下文

| 消息操作 | 行为 |
| --- | --- |
| `getRaw()` | 读取原始消息数据，仍包含平台上报的原始字段 |
| `getMessageEventType()` | 区分群 @、全量群消息及 C2C 等接收事件类型 |
| `recall()` | 执行构造时绑定的撤回操作，返回是否成功 |

自行构造 `QQMessage` 时，在 `EventType` 之后传入 `JsonNode raw` 和 `Recallable recallAction`。旧的 `String conversationId, JsonNode raw` 构造方法已标记弃用；接收上下文通过撤回回调提供操作目标
