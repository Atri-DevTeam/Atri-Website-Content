# 指令

[文档目录](../%E4%BB%8B%E7%BB%8D.md)

## 声明资源

在 `src/main/resources/atribot.yml` 声明指令，其他资源路径可通过 `BotCommand.commandResource()` 指定

```yaml
commands:
  ping:
    description: "检查机器人响应"
    usage: "/ping"
    aliases: ["p"]
    prefixless-aliases: ["测试响应"]
```

| 字段 | 含义 |
| --- | --- |
| 主键 `ping` | 主指令名 |
| `description` | 指令说明 |
| `usage` | 执行器返回 false 时使用的用法 |
| `aliases` | 带指令前缀的别名 |
| `prefixless-aliases` | 无需前缀的完整触发词，不允许包含空白字符 |

::: info 无前缀指令的匹配方式
无前缀触发词按消息的第一个空白分隔词查找，不执行全量正则匹配，重复触发词冲突会使注册失败
:::

声明资源必须对 `CommandManager` 的类加载器可见，外部文件不会自动按路径读取

## 注册执行器

调用 `provider.initialize()` 后绑定执行器，指令监听器已由 core 自动注册：

```java
import top.yzljc.atricore.command.CommandManager;

CommandManager.getCommand("ping").setExecutor((sender, command, label, args) -> {
    if (args.length != 0) return false;
    sender.sendMessage("pong");
    return true;
});
```

在初始化与启动之间执行上述注册代码，指令监听器由框架统一注册

指令不存在时 `getCommand()` 返回 null，应先保证声明资源已加载，`CommandManager.reload()` 会重新读取声明并按主指令名保留已绑定的执行器

## 执行参数

```java
boolean onCommand(CommandSender sender, Command command, String label, String[] args)
```

| 参数 | 含义 |
| --- | --- |
| `sender` | 指令来源及回复能力 |
| `command` | 匹配到的主指令 |
| `label` | 本次分发标签，可能是别名或无前缀映射后的名称 |
| `args` | 标签之后按空白拆分的参数，不含指令本身 |

`/p one two` 对应主指令 `ping`、标签 `p` 和参数 `[one, two]`

::: note 参数拆分
参数按空白字符拆分，引号不会将多个词合并为一个参数
:::

执行器返回 true 表示已经处理，返回 false 时 `CommandFeature` 发送非空的 `usage` 提示

::: important 分发结果与业务结果
`CommandManager.dispatch()` 的返回值含义不同：true 表示已找到并处理分发入口，也包括业务禁用、事件取消或执行异常，不代表业务成功
:::

## 判断与主动分发

```java
boolean commandInput = CommandManager.isCommand(text);
String commandLine = CommandManager.resolveCommandLine(sender, text);
if (commandLine != null) {
    CommandManager.dispatch(sender, commandLine);
}
```

`isCommand()` 只判断显式前缀或无前缀触发词，不验证指令是否存在，也不验证执行权限

`dispatch()` 接收已经去除显式前缀或完成触发词映射的指令行，直接调用时不会重复处理 `/`

平台事件入口会处理各自的消息文本，直接调用上述方法时应先去除平台提及标记

## 平台发送者

| 类型 | 场景 |
| --- | --- |
| `QQCommandSender` | QQ 群聊和 C2C |
| `QQGuildCommandSender` | QQ 文字子频道和频道私信 |
| `NapcatCommandSender` | Napcat 群聊和私聊 |
| `ConsoleCommandSender` | 控制台 |

公共能力包含用户标识、名称、权限判断和文本回复，Markdown、图片、会话标识等能力通过对应接口使用

`getPlatform()` 在控制台等无平台来源下可能返回 null，业务指令应检查平台类型后再使用特定能力

`QQCommandSender` 发送带按钮的 Markdown 时，通过 `markdown.setKeyboard(keyboard)` 设置键盘，再调用 `sendMessage(markdown)`，不再单独传入键盘参数

### QQ 群上下文与平台身份

| 方法 | 返回与含义 |
| --- | --- |
| `getGroup()` | 群聊返回当前事件传入的 `QQGroup`；C2C 返回 null |
| `getGroupId()` | 群聊返回群 OpenID；C2C 返回 null |
| `getMemberRole()` | 群聊读取 QQ 平台的 `member_role`；C2C 返回 `PlatformRole.OWNER` |
| `getMessage()` | 当前 `QQMessage`，消息对象不保存群标识 |

```java
if (sender instanceof QQCommandSender user
        && user.getPlatform() == Platform.OFFICIAL_GROUP) {
    var group = user.getGroup();
    String unionGroupOpenId = group.getUnionGroupOpenId();
    user.sendMessage("群标识：" + group.getGroupOpenId());
}
```

群对象由平台入口创建，经过事件传给指令发送者，获取对象与读取标识均为内存操作。调用 `fetchGroupProfile()`、`getMemberInfo()` 等方法时才请求平台，完整入口见 [QQGroup](../QQ%E5%AE%98%E6%96%B9%E6%9C%BA%E5%99%A8%E4%BA%BA/%E6%9C%BA%E5%99%A8%E4%BA%BA%E4%B8%8E%E7%BE%A4%E8%B5%84%E6%96%99.md#qqgroup)

自行创建发送者时使用 `QQSenderImpl(QQUser user, QQGroup group, QQMessage message)`，实现位于 `top.yzljc.atricore.command.impl`；群聊传入已有群对象，私聊传入 null

`getMemberRole()` 是 QQ 平台身份，机器人统一账号的角色和权限仍通过账号服务及 `hasPermission()` 判断

::: important 消息操作栏仅私聊
文本、Markdown 和 ImageComponent 的 `sendMessage` 方法可在末尾追加 ActionButton。私聊发送操作栏，群聊忽略此参数并正常发送正文，具体字段见 [私聊消息操作栏](../QQ%E6%B6%88%E6%81%AF%E7%BB%84%E4%BB%B6/%E7%A7%81%E8%81%8A%E6%B6%88%E6%81%AF%E6%93%8D%E4%BD%9C%E6%A0%8F.md)
:::

## 权限与事件

业务权限在执行器中通过 `sender.hasPermission(permission)` 检查，也可在 `UserRunCommandEvent` 中统一检查

匹配指令后同步触发 `UserRunCommandEvent`，取消该事件会阻止执行器调用，监听规则见 [事件](%E4%BA%8B%E4%BB%B6.md)

QQ 私聊指令通过上述事件检查后，默认使用当前消息作为被动回复来源，异步发送持续 3 秒的输入状态通知，同时继续执行指令。通知失败或任务提交被拒绝时不重试，不影响指令回复；未匹配、被取消的指令及其他平台不发送此通知

通过 `qq.command-input-notify` 或 `AtriSettings.setQqCommandInputNotify(boolean)` 控制开关，每次执行时读取当前配置

## 按平台注册扩展指令

`ScopedCommand` 声明限定名称和支持平台，`CommandManager.registerPluginCommands(owner, commands)` 按所有者注册，卸载时使用对应的 `unregisterPluginCommands`

指定平台的指令在该平台查找时优先，空平台集合表示通用指令，限定名称使用 `owner:name`

core 提供注册机制，不包含插件目录扫描、类加载或插件生命周期管理
